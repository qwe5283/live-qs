# 15 — 交付来源优先级与覆盖度

**What to build:** 让 Owner 明白每项摘要选择了哪个来源、有哪些冲突或缺口，并能依靠显式版本化策略获得稳定规范化结果，而不是静默模糊去重。

**Blocked by:** 12 — 接入 Android UsageStats; 13 — 接入 Health Connect; 14 — 接入微信支付结构化事件.

**Status:** ready-for-agent

- [ ] 所有来源观测保持独立并可追溯，规范化结果引用其 source event identifiers。
- [ ] 每类指标具有明确、版本化的来源优先级，不使用通用相似度删除观测。
- [ ] WebUI 展示所选来源、策略版本、数据覆盖范围、冲突和待确认数量。
- [ ] 查询响应区分零值、无数据、部分覆盖和来源冲突。
- [ ] 更改来源策略只重建派生结果，不修改原始观测。
- [ ] Android 应用时长、Health Connect 多 origin 和模糊支付候选均有确定测试样例。
- [ ] 审计能够说明策略改变影响的时间范围和结果数量。
