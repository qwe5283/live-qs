# LiveQs Windows

Windows 本地优先的前台应用时间统计工具。应用以单用户托盘进程持续运行，前台窗口采样、查询和维护只依赖本地 SQLite；云同步为可选功能，服务端故障不会中断本地能力。

## 技术与结构

- .NET 9、WPF、C#
- Microsoft.Data.Sqlite，WAL 模式
- Win32 API 前台窗口、空闲时间和全屏检测
- Core：模型与服务契约
- Infrastructure：采样、SQLite、云同步、维护和开机自启
- App：WPF 页面、图表、主题和托盘生命周期

本地数据默认位于 `%LocalAppData%\LiveQs\Windows\liveqs.db`。窗口标题可配置为本地原文、哈希或不记录；云同步始终只发送标题哈希。

## 时间线活动段落

一条活动段落是一组时间上相邻的本地活动记录，合并为一张时间线卡片。段落表达观测到的应用使用连续性，保留底层原始记录；项目、任务或专注需要另有语义依据。

| 情况 | 段落边界 |
|---|---|
| 同一应用连续使用，窗口标题变化 | 合并，标题变化只累计次数 |
| 多个应用短时来回切换 | 合并为「多应用活动」 |
| 同一应用连续使用累计 **≥5 分钟** | 独立成段，与前后其他应用活动分开；按实际非 AFK 记录累计时长 |
| 连续 AFK 状态持续 **≤5 分钟** | AFK 本身不形成边界，前后活动按其余规则合并；预览色带和应用泳道留白，AFK 不计入活跃时长或应用占比 |
| 连续 AFK 状态持续 **>5 分钟** | 切分，AFK 单独成段 |
| 已配对的锁屏、睡眠、现代待机或关机/启动证据覆盖无记录间隔 | 作为 AFK 与相邻离开时段合并；亮屏、锁屏窗口出现本身不代表恢复使用 |
| 现代待机 **506 → 507** 退出后的未观测时间 | 不预留采集恢复窗口；系统证据只覆盖到 507 原始时刻，之后按通常的 30 秒缺口规则处理 |
| 传统睡眠/休眠恢复或开机日志之后的未观测时间 **≤2 分钟** | 并入离开时段作为「恢复缓冲」；第一条实际采样提前结束窗口，已观测活跃记录正常计时 |
| 传统睡眠/休眠恢复或开机后 **超过 2 分钟**仍未采样 | 在窗口终点切分，剩余缺口独立展示；不再叠加 30 秒短缺口容忍 |
| 无记录间隔 **>30 秒**，且没有系统证据覆盖 | 切分，中间显示「无活动记录」；部分覆盖时保留未解释的剩余缺口 |
| 无记录间隔 **≤30 秒** | 不因间隔切分，但轨迹留白，空白时间不计入覆盖或活跃时长 |
| LockApp、LogonUI 或当前用户会话锁定 | 视为 AFK，全屏标记不改变这一判断；历史原始标记仍可查看 |
| 多应用段落接近 **60 分钟** | 在记录边界拆分；连续单应用长段可以超过 60 分钟 |

AFK 阈值按连续 AFK 段的起止跨度判断，多条相邻 AFK 记录合并后再判断。短 AFK 优先并入前一应用连续段，只有后一段可相邻合并时并入后一段；没有相邻活动可合并时仍单独展示。

段落起点和终点由记录、已配对的系统证据和有限恢复窗口共同确定。跨度包含段内短 AFK 和短间隔；「采样覆盖」只累计实际记录，包含已记录的 AFK；「系统补充」只累计系统证据覆盖但没有采样的时间；「恢复缓冲」只累计恢复窗口内未被采样或系统状态覆盖的时间，分别按并集计量，不重复计时。活跃时长只累计非 AFK 且未被系统状态覆盖的采样。预览色带、应用泳道和应用时长均排除 AFK，展开原始记录仍可查看 AFK 的起止和状态。仪表盘采用相同的非活跃判定，系统补充和恢复缓冲不增加应用用量或采样 AFK 总量。

例如同一应用使用 10 分钟、AFK 3 分钟、继续使用 10 分钟，合并为一个跨度 23 分钟、活跃 20 分钟的段落，中间 3 分钟留白。不同应用的长段、无记录缺口和多应用时长上限仍可形成边界。

时间线按所选日期裁剪，跨日离开时段提示「从前一天延续」或「延续至下一天」。单设备前台重叠按较晚开始的记录优先绘图和计时。分页加载更早记录后会重新合并段落，尚未加载完整的最早段落有提示；未加载时段不会先算成系统补充。同一浏览器内从开发页面切到小红书的标题变化，仍按同应用记录折叠。

重叠先于日期裁剪处理，AFK 的持续时间和跨日延续依据实际有效边界判断，不使用已被较晚记录取代的估计尾部。原始详情独立保留有效观测；即使两条记录起点完全相同、其中一条的计量区间被裁为零，仍可查看两条原始记录，覆盖、活跃时长及变化次数只使用有效切片。

## Windows 系统状态证据

后台进程实时监听当前会话锁屏/解锁和系统挂起/恢复，采样同时查询会话锁定状态。首次运行补查最近 **30 天** Windows `System` 日志，此后每 **5 分钟**增量导入，并重读检查点前 **15 分钟**，重复事件按稳定标识去重。

| Windows 日志来源 | 事件 | 解释 |
|---|---|---|
| Kernel-Power | 506 / 507 | 进入 / 退出现代待机 |
| Kernel-Power | 42 / 107 | 进入睡眠或休眠 / 恢复 |
| Power-Troubleshooter | 1 | 使用日志内报告的 SleepTime / WakeTime 补充完整睡眠区间 |
| Kernel-General | 13 / 12 | 正常关机 / 系统启动 |

系统证据单独保存在本地 SQLite，仅含结构化时间、状态、来源、事件 ID 和稳定标识；不保存事件日志正文或账户信息，不加入云同步队列。它补充时间线解释，不生成虚构的前台采样，也不改写原始活动记录、revision 或同步载荷。展开段落并选择时间窗口后可查看系统证据及其来源。

系统证据和匿名采样时刻标记与活动数据统一清理：设置中的「删除数据」按选定本地日期转换的 UTC 左闭右开范围删除系统事件，保留策略按同一截止时刻删除较早事件。导入检查点保留；删除时间边界与清理在同一事务中持久化，后续日志补查、重启及删除时已经进行的导入都不会回填已删证据。只记录删除范围的时间，重叠或相邻范围合并，保留截止时间只向前推进；这些边界不上传。删除包含当天或未来日期时，防回填范围截至执行时刻（含该时刻），之后的新采集继续正常保存。删除结果中的数量仅统计活动记录，系统证据和时刻标记同时清理。本地删除不改变服务端已接收的历史，也不清除 Windows 自身的系统日志。旧版本未记录删除边界，已删除日期如仍有系统证据残留，需重新执行一次范围删除。

时间线和仪表盘把删除范围作为系统证据的边界：不能用范围两侧剩余事件重新配对成连续离开时段；失去安全闭合依据的状态按未知处理，范围外完整配对继续可查。采集恢复窗口在首次遇到删除边界时终止，删除首条采样不会重新延长窗口；不超过 30 秒的缺口也不能跨删除范围合并段落。

只有同一来源中配对闭合的状态才解释其起止之间的历史缺口。传统睡眠/休眠恢复（Kernel-Power 107、Power-Troubleshooter 1）和开机（Kernel-General 12）日志可另支持从原始日志时刻开始、最多 **2 分钟**的采集恢复窗口，给恢复调度或开机自启动预留时间；到首条实际采样或查询时刻提前结束。现代待机 **506 → 507** 不适用这一缓冲，退出之后的未观测时间按通常的 30 秒缺口规则处理。窗口是本地展示规则，日志原始时间保持不变；展开选区以「采集恢复窗口」为标题，可查看恢复缓冲范围和锚定它的日志事件。解锁事件及实时状态通知不适用这一日志缓冲。未配对的单个适用恢复/开机事件只支持其后的有限窗口，不能解释之前的缺口。

例如 08:00 开机，08:01:30 开始采样，前 1 分 30 秒并入离开时段；若 08:02:01 才开始采样，离开时段最多补到 08:02，08:02–08:02:01 独立显示为「无活动记录」，随后开始新的活动段落。第一条采样为 AFK 时也结束恢复窗口，其后再次缺采样按通常缺口规则判断。

恢复窗口的终点按完整采样上下文确定，不随查询日期、分页或应用排除规则改变。前一天已经发生的首条采样仍可终止跨午夜的窗口；采样时已排除的应用只保留采样时刻，不保存应用、标题或路径，不上传，该时刻标记随活动保留策略和日期范围清理。

没有恢复/启动证据的单个开始事件、手动暂停、退出采集器、突然断电或日志缺失，仍保留为未知；日志读取失败时显示提示并自动重试，采样和已有本地查询继续工作。

例如 10 月 7 日 23:46 开始 AFK，10 月 8 日 00:15 进入现代待机，00:18 出现短暂锁屏窗口，00:32 退出待机并解锁，可以合并为连续「离开电脑」。在 10 月 8 日的页面按午夜裁剪展示一段，并保留前一天延续提示、实际采样覆盖与系统补充的分别计量。

## 开发

```powershell
dotnet restore LiveQs.Windows.sln
dotnet test LiveQs.Windows.sln
dotnet run --project LiveQs.Windows\LiveQs.Windows.csproj
```

后台启动：

```powershell
dotnet run --project LiveQs.Windows\LiveQs.Windows.csproj -- --background
```

## 发布

```powershell
dotnet publish LiveQs.Windows\LiveQs.Windows.csproj `
  -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true `
  -o artifacts\win-x64
```

云同步兼容现有服务端的 `POST /api/v1/ingest/events`，使用 Bearer Device Token。同步采用 SQLite outbox、幂等键和指数退避。
