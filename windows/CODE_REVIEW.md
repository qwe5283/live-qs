# Windows Code Review 清单

适用范围：windows/ 中的 Core、Infrastructure、WPF App 和 Tests。
判断当前行为时先读实现、调用路径和测试；文档与代码冲突时记录差异，不把过期文档当作缺陷依据。
新增需求仍须对齐协议及明确的业务要求。

## 必须检查

- [ ] 改动有明确的问题、触发条件和预期结果，范围没有蔓延到其他组件。
- [ ] 四空格缩进、Allman 大括号、文件作用域命名空间，using 无冗余且排序一致。
      用 .editorconfig 和格式检查执行这些规则。
- [ ] 类和方法使用 PascalCase，参数和局部变量使用 camelCase，私有字段使用 _camelCase。
      常量使用 PascalCase，WPF 公共依赖属性遵循框架命名。
- [ ] 编译器及分析器警告已处理，不能用无理由的禁用或吞异常掩盖问题。
- [ ] 依赖方向清楚：Core 不依赖 WPF、SQLite 或 HTTP；Infrastructure 实现 Core 的接口；
      App 负责界面和应用生命周期。不存在循环依赖。
- [ ] 配置、HTTP 客户端策略及时间序列化使用已有集中入口。
      引入自定义基础设施前先检查 .NET、现有依赖和成熟 NuGet 方案。
- [ ] SQLite 多步状态修改有明确事务边界。采样、关闭区间、维护、上传同时运行时仍保持一致。
- [ ] 事件 ID 稳定，revision 单调递增，ack 和永久拒绝只影响实际发送的 revision。
      采样延长区间不能重置上传退避；逐项失败不能丢弃其他待上传记录。
- [ ] 统计、时间线和分布图使用同一裁剪与重叠策略；原始记录保留，AFK、排除应用及缺口语义明确。
      日期边界、跨午夜和夏令时使用正确时区。
- [ ] 原始标题、可执行路径及凭据不进入上传载荷或日志。心跳不进入历史时长。
- [ ] HTTP 期限覆盖响应体和下载；取消能停止等待并清理临时文件。
      关闭时的取消不报告成业务或网络故障。
- [ ] 结构化日志使用 ILogger 占位符，关联设备、批次、事件和 revision；
      日志输出保留 scope 属性。错误码与展示文本分别保存。
- [ ] UI 查询失败不会把旧日期数据显示为新结果；加载、空结果、错误和重试状态可区分。
      后台通知通过 Dispatcher 更新界面，事件订阅与资源生命周期配对。
- [ ] 不手工修改生成模型、构建产物、数据库或凭据文件。

## 需要判断的可读性问题

- [ ] 名称直接说明业务意图：类用名词，方法用动宾短语，字段表达所持有的数据。
- [ ] 方法围绕一个职责组织。把复杂的查询、映射或状态转换提取为有意义的方法，
      避免为行数指标拆出仅转发参数的包装。
- [ ] 集合过滤、映射、排序优先使用可读的 LINQ；嵌套映射先命名中间结果或映射函数。
- [ ] 简单方法使用表达式体，简单委托使用 Lambda；复杂流程保留易读的语句和空行。
- [ ] 注释解释业务约束、设计决策或 workaround 的原因，不能逐行复述代码。
- [ ] 单行以 120 字符为阅读目标。长参数列表和条件主动换行；
      不能为了硬性行宽破坏字符串、协议字段或清晰的表达。
- [ ] 类型按职责组织，抽象有稳定边界和具体收益；删除重复逻辑及无实际用途的层次。

## 测试与验证

- [ ] 每个行为修复先有能复现失败的回归用例，断言可观察结果，避免绑定私有实现。
- [ ] 按 Given / When / Then 组织测试准备、操作和断言，可用空行表达阶段。
      使用固定时钟、独立临时目录和数据库；释放连接、文件及 HTTP 资源。
- [ ] 优先覆盖 revision 竞争、重试期限、区间重叠、隐私边界、超时和错误状态。
      不为纯格式调整或参数转发添加镜像测试。
- [ ] 从 windows/ 运行 ..\scripts\check.ps1 windows，完成测试和构建检查。
      使用 dotnet format whitespace/style LiveQs.Windows.sln --verify-no-changes 检查格式，
      排除 LiveQs.Windows.Core/Generated；style 检查 IDE0011、IDE0005、IDE0161 和 IDE0065。
- [ ] 界面可见变化附截图；Win32 采样、音频、单实例、托盘、启动和退出使用真实桌面冒烟验证。
      自动化测试不能替代真实设备和七天验收。

Review 反馈应指出具体文件、触发场景、影响及建议；区分行为缺陷、硬性规范和判断性建议。
格式化工具已能检查的问题交给工具，人工 Review 聚焦行为和边界。
